# supOS 企业组织架构（org）快速手册（给模型用）

目标：处理“公司/部门/人员/岗位”等组织架构问题时，优先只读本文件，
避免整篇 `supOS_企业组织架构_API文档.md` 喂给模型导致 token 浪费与命中不准。

## basePath

`/os/open-api/org/v1/`

## 使用规则

- 只用内置工具 `supos_api_call` 调用 Open API。
- 先用本手册确定接口与参数；不足时再去长文档按小节精读。

## 高频场景 → 建议接口

### 1) 查岗位（按编码）

- **GET** `/positions/{code}`

```text
method: get
path: /os/open-api/org/v1/positions/{code}
data: null
```

### 2) 分页查岗位列表（含筛选）

长文档里岗位分页接口很多字段很长；一般先用分页接口 + `brief=true` 降低返回复杂度。
当用户只要岗位的部门信息，不要角色/创建人/修改人详情时，优先 `brief=true`。

（如需具体分页路径与参数，去读长文档对应“岗位API-分页查询”小节。）

### 3) 查人员（按编码）

通常在“人员API”小节。
建议先按编码查询，必要时再展开关联用户信息（部分接口支持 `brief=true`）。

（如需具体路径与参数，去读长文档对应“人员API-根据编码获取人员”小节。）

### 4) 查部门/公司树、部门成员

组织树/成员查询属于高频需求，但不同版本接口命名差异较大。
当用户要“公司-部门-人员树”时：
- 先读长文档里“部门API/公司API”对应小节，找到树或列表接口
- 再用 `supos_api_call` 调用
